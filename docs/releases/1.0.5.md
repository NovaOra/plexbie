**New in 1.0.5**

Plexbie 1.0.5 is the first update since 1.0.0, numbered to match the phone app, so a household's Plexbie and app now share one version number: fixes and hardening across the bot, the website and setup, plus new things for admins and members.

**Before you update**

Some things now work differently. Please read these before you press Update, especially if you use inactivity removals or media cleanup.

- **Your Discord server only:** slash commands, autocomplete and admin buttons now work only in your household's server (`GUILD_ID`). Make sure it is set (the setup page fills it in). If it is blank and Plexbie can't tell which server is yours, commands and admin buttons stay off until you set it, and the log and Manage → Health say why. Leftover global commands are removed at start-up. The Administrator permission and `ADMIN_ROLE_ID` now count only in that server; `BOT_OWNER_ID` still works everywhere.
- **Other servers:** if someone adds Plexbie to another server, it refuses everything there, tells the admins and lists it on Manage → Health. Turn off Public Bot in the Discord Developer Portal: Installation → Install Link: None, save, then Bot → Public Bot off, save. Health and the setup page warn while it is on. Only members of your server and the bot owner can reach the admins by DMing Plexbie; other DMs are only noted in the log. Invite tracking and watch-party voice events also count only in your server.
- **DMs to Plexbie:** Plexbie now keeps the DMs people send it for 90 days, where admins can read them, and answers someone's first DM in 12 hours with a short note that the admins have it. Give Plexbie's role **Create Public Threads** and **Send Messages in Threads** in the admin channel (Manage → Health tells you if they're missing). To skip the automatic reply, turn off "Answer DMs automatically" on Manage → Discord. Your Plexbie's privacy page says DMs are kept, but you may want to tell your household. The admin channel no longer gets a receipt for every DM Plexbie sends; DMs that didn't get through are marked on Manage → Messages.
- **Admin commands:** `/requests`, `/remove-user`, `/list-tracked-users`, `/list-plex-users`, `/manage-links`, `/watchparty-active` and `/say` now work for the `ADMIN_ROLE_ID` role and `BOT_OWNER_ID` as well as Discord administrators, the same as the admin buttons. Discord still hides them from anyone who isn't a Discord administrator. To show them, allow them under Server Settings → Integrations → Plexbie. Admin-role holders can now use `/say`, which posts with Plexbie's own channel access and can ping @everyone. If you don't want that, turn off the `status` plugin, which provides it.
- **Admin sign-in alerts:** every time someone signs in to the website or the app as an admin, Plexbie sends that admin a Discord DM (if their account is linked) and alerts every admin who has alerts turned on, naming the browser or device. If you see one you don't expect, press and hold **Sign out every other session** on Manage → Health: it ends every website and app sign-in except yours. If you can't reach Manage, change `WEB_SESSION_SECRET` and restart. That ends every website sign-in, but not phone app sign-ins.
- **Inactivity removals:** members who have never watched anything are now warned and removed like any other idle member, with the usual exemptions. The check also now reads every Tautulli user, not just the first 25, so idle members past the first 25 are now warned too. Everyone already on the server with no watch history gets a full inactivity period from the first daily check after you update, so they are all warned on the same day. Two new brakes protect against bad data. If Tautulli hasn't recorded a play by anyone for more than 7 days, nobody is warned or removed. If one pass would remove more than 3 people, or a quarter of everyone tracked when that is more, nobody is removed. Either way the admins are told, and you can remove people by hand in Manage → People. Members Tautulli doesn't list are only counted when Plexbie has a plex.tv sign-in, anyone with Keep History off in Tautulli is left alone, and a name two Tautulli users share now matches neither. Exempt anyone who should keep access before you update.
- **Requests from Discord:** while the website is running, `/request` goes through the same checks as the website: at most 20 an hour per member across both, nothing they already asked for that is still open, nothing blocked in Seerr, and no film or chosen seasons already on Plex or requested. Members may now get a refusal on Discord where the request used to go straight to the admins. Without Seerr, or when it can't be reached, the Seerr checks are skipped. Film and TV search now needs `TMDB_API_KEY`; without it, **TV & Movie** says so instead of searching. Book search needs no key.
- **Sonarr and Radarr monitoring:** "Latest season + new episodes" now really follows the show. Sonarr keeps the series monitored for every new season, and the 90-day request expiry no longer switches it off. At the next daily check, shows already approved this way get new-season monitoring, and are monitored again if Plexbie had turned them off. Request expiry now also leaves monitoring on for titles anyone played in the last 90 days, titles kept forever and titles in a skipped cleanup library. It turns monitoring back on only for titles Plexbie turned off itself, so a series you switched off by hand stays off. In practice mode it now only reports what it would change; 1.0.0 changed monitoring in practice mode too. The first time it runs live, every title that is already unmonitored and whose newest request is over 90 days old counts as one Plexbie turned off. Any of those that were played in the last 90 days, are kept forever, sit in a skipped library or follow new seasons are switched back on, and Sonarr or Radarr may start searching for them. Check those after the first daily check: switch one off again by hand and it stays off.
- **Skipped cleanup libraries:** a skipped library that no longer matches anything in Plex now stops every cleanup removal until you let it go under Manage → Cleanup, and the admin channel is told once. If you renamed or deleted a skipped library in Plex before this version, pick it again under its new name or let the old one go, or cleanup will remove nothing.
- **Cleanup warnings and limits:** a title is now removed only after its full warning period (7 days by default) has passed since its first warning. So lowering the inactivity days, or adding a library, warns first and removes nothing that day. The daily check now removes nothing when it would remove more than 5 titles and more than a tenth of the titles it looked at. It lists them in the admin channel instead, and a manual scan (Scan now under Manage → Cleanup, or Run Scan Now on Discord) removes them. If cleanup hasn't run for more than 3 days, every title that is due gets a fresh full warning. Right after you update there is no record of earlier warnings, so every title already being warned about gets a fresh warning and its countdown starts again. Warnings made in practice mode now carry over: when you go live, the next daily check removes the titles practice mode has warned about for the whole warning period, within its daily limit. An empty Plex watch history pauses cleanup and posts a "Media Cleanup Paused" notice.
- **Cleanup and Seerr:** when cleanup removes a title it now clears it from Seerr too. The daily check also clears Seerr's leftover records of titles that are gone from Plex and that Sonarr and Radarr no longer have, however they were removed, so they can be requested again. This works like Seerr's own Clear data. It starts with the first daily check after you update, and runs only when cleanup is on and not in practice mode. Only one scan runs at a time, and Scan now is refused while cleanup is off, so switch it on first (practice mode is fine).
- **Tickets:** what used to be under Needs help is now on Manage → Tickets. Plexbie now opens tickets and alerts the admins by itself when Sonarr or Radarr block an import, and when an approved request never reaches them. Right after you update, each download already stuck as import blocked gets its own ticket on the first check (or, without a Plexbie request, a note in the admin channel). Plexbie never imports one without an admin.
- **Bookshelf folders:** Bookshelf no longer files books into a blank, relative or missing folder. Check that the `BOOKSHELF_*_WATCH` and `BOOKSHELF_*_LIBRARY` settings are full paths to folders mapped into the container. Plexbie doesn't create the library folders, and holds finished downloads until they exist.
- **Tautulli webhook:** if the log warns that Tautulli sends its webhook secret on the URL, press Connect live updates on the setup page and remove the hand-made Tautulli webhook, or set its JSON headers to `{"Authorization": "Bearer <secret>"}`. The webhook port is plain HTTP. Keep it on your LAN or Tailscale, or behind a TLS reverse proxy that keeps the `/webhook/seerr` or `/webhook/tautulli` path.
- **Proxy and config:** if Manage → Health shows a Proxy item, sign-in cookies are going out without Secure. Set `WEB_PUBLIC_URL` to your site's https:// address, and add the proxy to `TRUSTED_PROXIES` if it should be trusted. On its next save, a `config/.env` that other users could read is tightened to owner read-write and group read-only. If an outside tool reads it as another user, give that tool group access.

**New**
- **Manage menu:** the sections of Manage are in a ☰ menu at the top right, each with its count, instead of a picker and a row of links in the middle of the page.
- **All requests:** Manage → All requests lists every request anyone made (waiting, on its way, on Plex or declined), with where it is now, who asked and why it looks stuck. From there an admin can search again or open a ticket.
- **Tickets:** tickets have their own tab on Manage, where admins can take a ticket, keep notes only admins see, reply to the member, mark it as waiting on them, and solve or reopen it. Members can open a ticket straight from Plexbie's approval DM and answer on Discord, the website or the app. Replies, "Solved" and new tickets say how the member was reached (Discord DM, phone alert or email). If nothing reached them, Manage shows "Not delivered".
- **Import help:** when Sonarr or Radarr won't import a finished download, the ticket shows what's in the download and what looks off. An admin can pick the episode or film, quality and language and import it with Sonarr's or Radarr's own Manual Import. An import is refused if its files changed since you looked, and Radarr imports refuse two files set as the same film. When an import times out or the connection drops, the panel says "No answer yet" and asks you to check Sonarr or Radarr before trying again. "Wrong show?" waits for the new show's episodes before you pick. If an approved request still isn't in Sonarr or Radarr ten minutes after Seerr took it, admins get a ticket, and if Seerr refused it because of an old record, the ticket says how to clear it.
- **DM inbox:** Plexbie's DMs work as a shared inbox. What people send shows on Manage → Messages and in a thread per person under the admin channel (only those who can see that channel see it), and admins can reply as Plexbie from either place or with `/reply`.
- **`/my-requests`:** members see their newest 10 requests and where each one stands, with a link to the website for the rest. It needs the website running.
- **Alerts and live progress:** new requests and join requests now alert admins on their phone or in the browser, not only in Discord. Members with the Android app can turn on live progress: one notification per request that updates while it downloads and is added to Plex, then goes away. Each update carries the time it was sent, so a late one can't bring back a finished notification.
- **Sign out every other session:** on Manage → Health, a press and hold ends every website and app sign-in except yours. It also stops the browser alerts and phone push those sign-ins turned on, and voids any phone app sign-in still in progress. Your own alerts stay on.
- **Cleanup on Manage:** you can keep any film or show forever by searching for it, the same as `/cleanup exempt add`. There is also a Turn on in practice button next to the hold-to-confirm Turn on, live.

**Fixed**
- **Setup:** the first-time setup page shows its form again. In 1.0.0 a script error left a new install with only the headings and no box for the setup code. `config/.env` is now written with private permissions from the start, and if the config folder can't be written, the page names the file and the reason instead of showing a bare server error.
- **Sign-in:** the full-page "Sign in with Plex" and the invite page's second button now start the Plex sign-in in your own browser, so a forwarded plex.tv link can't sign someone else in. Only a member's or admin's sign-in now marks an address as part of the household, so an outside account can't use up the household's share of Discord sign-ins. A website logout that can't be saved now says so and can be tried again. While the list of signed-out sessions can't be read, website sessions are asked to try again in a moment instead of being let in unchecked.
- **Security:** connecting Tautulli from the setup page no longer puts the webhook secret in a URL. Bookshelf trusts only request details Plexbie wrote itself, and fetches covers only from public internet addresses (JPEG, PNG or WebP up to 15 MB). Nothing Plexbie posts can ping @everyone or a role unless that post is meant to. Each member has hourly limits on searching, "More like this", Discover shelves and saving language choices. Someone signed in without Plex access can only load their own profile picture.
- **Alerts:** logging out of the website turns off that browser's alerts, and alerts show as on only for the member who turned them on. Alerts a member turned on with an older Plexbie keep arriving but show as off until they turn them on again. Members can replace their iPhone SideStore source address from the Alerts page, which ends the old one, and new addresses no longer include the member's name.
- **Request decisions:** each request can only be decided once, from Discord, the website or Seerr, and a second Approve or Decline says it is already decided. A book approval that finds nothing stays open, so you can approve it again later. Members see "Request submitted" only once their request has really reached the admins. When an import is blocked or a download has a problem, members get a plain sentence; what Sonarr or Radarr said, including release names and folders, is shown only to admins.
- **Shows and films:** approving a show that isn't on TheTVDB no longer sends it to Seerr, where it would quietly disappear. The admin card says it needs a hand download, and the member is told an admin will add it. An approved show Sonarr doesn't have now says why. A film and a show that share an ID are no longer mixed up, and "All Seasons" or hand-picked seasons are only refused when every season asked for is already on Plex or requested. The season picker works for shows with no regular seasons or more than 25 seasons, and members who request a show with all its seasons get a DM when it arrives on Plex.
- **Manage:** the section on screen refreshes every minute and when you come back to the page. If a refresh fails, Manage says so instead of showing old numbers, and Health names whether Sonarr or Radarr couldn't be read. Manage → People shows each member's real last-watch time. Searches show results only for the words currently in the box. Requests made in Seerr link to their announcement in the admin channel, or show no link if they were never announced. `/requests` no longer counts older requests as untracked, and a book card whose Approve can't load the request says to try again or decide on the website.
- **Manage controls:** a row's buttons stay disabled until that row's own action finishes, hold-to-confirm buttons can't fire once disabled, and a swipe acts on a request only past the line. One Alt+Z press undoes one change, and Alt+Z follows the key labelled Z on AZERTY keyboards. A typed number of cleanup days saves when you leave the field, a failed save goes back to the old value, and a reply can't be sent twice. Turning cleanup on while practice mode is off takes the same press and hold as Go live. Invites with a bad number of days or a bad email get a clear error with the allowed limits.
- **Removals:** `/remove-user` and the website's Remove button now find the person by their Plex account instead of a stored email, and an inactivity removal takes off the account whose inactivity was measured. The Plex server owner can't be removed, and is never warned or removed for inactivity, even when Plex can't be reached. An inactivity removal is skipped when the watch history belongs to a different account, and when an inactivity warning reaches nobody, the alert points to Manage → Messages.
- **Invites:** an invite link locked to an email now works only once the person's Plex account has confirmed that email, and an invite that fails part way is no longer used up. Plex invites sent to a username are listed by name in Manage, with a note to change or cancel them on plex.tv, and are never matched to the wrong member. Approving invites and listing libraries no longer stall the bot and website when Plex is slow.
- **Cleanup safety:** cleanup no longer deletes a different title that shares a name, such as a remake. If Sonarr or Radarr can't remove a title, Plex's copy stays, and only titles that were really removed are announced. When a title is in Plex more than once (a 4K library, overlapping folders), every copy is looked at together, so an idle copy can't take a watched copy with it.
- **What cleanup counts:** cleanup now counts what anyone in the household watched, not just the server owner. A show counts as fresh when a new episode arrives, and nothing is removed on a day Plex's watch history can't be read. The daily cleanup and the website's countdown now judge each title the same way.
- **Cleanup settings:** your keep-forever list, skipped libraries, practice mode and on/off switch no longer go back to their defaults when someone changes them soon after a restart. If the saved settings can't be read, cleanup now does nothing and the log says so, instead of starting over from the defaults. A title kept forever stays kept when it is added back to Plex under a new key (for titles kept from this version on), and a skipped library stays skipped when you rename it in Plex.
- **Filing books:** multi-disc audiobooks and ebooks whose files share names are filed without overwriting each other. If filing fails part way, it is undone and later retried into the same folder, so no files are lost and no "Title (2)" copy appears. Bookshelf checks a download again after looking up its details, so it never moves a download that is still arriving.
- **Book lookups:** Plexbie only uses an Open Library or Google Books result whose title matches, ignores ISBNs with a wrong check digit, reads multi-author audiobook tags with commas, and keeps folder names readable. NZBHydra is searched through the same connection as the rest of Plexbie, and one bad search result no longer hides the others. The requester's DM and the updates-channel post are sent separately, so one failing no longer stops the other, and a cover too big to upload is left off.
- **Website:** opening a member link while signed out returns you to that page after signing in with Discord or Plex, and closing the Plex sign-in window ends its wait. Browser alerts keep arriving after the browser renews its alert address. iPad is offered the Home Screen route like iPhone, and the site opens at its home page when added to a Home Screen. Each title page opens fresh when you move from one title to another, and messages from inside an open sheet are shown and read out.
- **On phones and in lists:** on phones held sideways the page clears the notch and rounded corners, hover effects no longer stick after a tap, and the blocked-import menus no longer make iPhones zoom in. Discover keeps the titles loaded with More, and Library stays quick when you change kind, genre or sort. Tapping the scrolling crawl or channel row no longer freezes it, and Play and Pause always do what they say. Covers drawn for titles without artwork fit any size.
- **Discord:** a new-season announcement now updates as the rest of the season reaches Plex. The invite tracker credits every join, including the one that uses up a limited invite, and no longer credits two close joins to the same invite. `/who-invited` shows "Unknown" instead of a broken mention when Discord gave no inviter.
- **Reliability:** on a host not set to UTC, last-watch, join, request and release times are no longer shifted by hours. An unreadable watch streaks file is left alone instead of being overwritten with an empty history, and saves can't leave it half-written. A phone app sign-in that can't be saved asks the app to try again, instead of handing out a sign-in that ends at the next restart, and no longer signs the person out of their other devices. A plugin that fails to load no longer leaves its tasks, listeners or commands running. If you write your own plugins, start `tasks.loop` loops at the end of `cog_load` (not in `__init__`) and stop them in `cog_unload`.

**Update**
- Unraid: press Update on the container (it installs `:latest`). Template updates now come from [NovaOra/unraid-templates](https://github.com/NovaOra/unraid-templates). If you added github.com/NovaOra/plexbie as a template repository, it no longer has the template, but your installed container keeps working.
- Docker: pull `ghcr.io/novaora/plexbie:latest`, or pin `ghcr.io/novaora/plexbie:1.0.5`.
- The phone app updates separately: see its [releases](https://github.com/NovaOra/plexbie-app/releases).
